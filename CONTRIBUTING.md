# Contributing

Thank you for helping improve the MagicMarkets data feed docs and examples.
By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Before you start

- Report security issues through [SECURITY.md](SECURITY.md), never in a
  public issue or pull request.
- For anything larger than a small fix, open an issue first so we can agree
  the approach.
- Never paste a token, password or stream URL (it contains the token) into
  an issue, pull request, test fixture or log.

## Set up

You need Python 3.10 or later, Node 20 or later, and `make`.

```bash
git clone https://github.com/magic-markets/magicmarkets-data-feed.git
cd magicmarkets-data-feed
python3 -m venv .venv
. .venv/bin/activate
make install
```

## Check your change

```bash
make check
```

`make check` runs lint, the Python and Node tests, the skill sync check, the
copy check and the link check. CI runs the same checks. Individual targets:

| Target | What it does |
|---|---|
| `make lint` | `ruff check` and `ruff format --check` on the Python code |
| `make format` | Applies `ruff` fixes and formatting |
| `make test` | pytest and `node --test`, against a local mock server |
| `make sync-skill` | Regenerates the skill's `references/protocol.md` and `examples/` |
| `make check` | lint, test, `sync_skill.py --check`, `check_copy.py` and `check_links.py` |
| `make test-live` | The opt-in live smoke test (`pytest -m live`). Needs `MM_DATA_TOKEN`. |

The tests never call the live feed. Only `make test-live` does, and only
with your own token in `MM_DATA_TOKEN`.

## Making a change

1. Create a branch.
2. Make the change. Python examples use only the standard library and
   `websockets`. Node examples use only `ws`.
3. Add or update a test for any behaviour change in `mmfeed.py` or
   `mmfeed.mjs`. Keep the Python and Node helpers in step.
4. If you changed `PROTOCOL.md` or `examples/python/`, run
   `make sync-skill`.
5. Run `make check`.
6. Open a pull request and fill in the template.

## Documentation rules

- `PROTOCOL.md` is the source of truth for the wire protocol. State only
  behaviour that MagicMarkets has confirmed. Keep volumes and timings
  indicative.
- Keep the section numbers in `PROTOCOL.md` stable. Other documents and the
  skill link to them. If you add a section, add it to the table of contents
  and check every cross reference.
- `claude-skill/magicmarkets-data/references/protocol.md` and
  `claude-skill/magicmarkets-data/examples/` are generated by
  `scripts/sync_skill.py`. Do not edit them by hand.
- Because `PROTOCOL.md` is copied into the skill, do not use relative links
  from it to other repository files. Use in-page anchors or absolute URLs.
- Use placeholders such as `<username>` and `<token>` in examples, never real
  account data.

## Copy rules

`scripts/check_copy.py` enforces most of these, and CI fails on a violation.

- No em dashes or en dashes, as characters or as HTML entities. Use a
  colon, a comma or two sentences. Ranges use a hyphen: `4-15 s`.
- No emojis, and no check-mark glyphs in tables. Write "yes" or "no".
- The brand is always `MagicMarkets`, one word.
- Write for sports trading and pricing. Do not use gambling language.
- Write plain, short, active sentences. Avoid filler and hype.

## Review

A maintainer reviews each pull request. CI must pass. We squash-merge by
default.
